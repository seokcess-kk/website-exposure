# Codex 자동 비평 요청 — apps/web walking skeleton 코드 cycle$N

## 당신의 역할

당신은 시니어 소프트웨어 아키텍트 검수자다. 본 monorepo 의 `apps/web/` 디렉터리에 새로 작성된 **walking skeleton 코드 30 파일**을 냉정하게 비평한다.

## 비평 운영 원칙

- 5사이클 고정이 아닌 **closeableAfterPatch 신호 누적 → 수렴** 기준.
- ready_for_acceptance=true 신호로 종결.
- 본 monorepo 비평 패턴 (cycle별 10~30 지적 normal).
- **얕은 trivia 보다 실질 결함을 우선 잡는다**:
  - Plan v1.0 명세와 코드 불일치
  - packages/auth · packages/db · packages/core-content · packages/shared-types 실 export 시그니처와 코드 호출 불일치
  - 보안 결함 (self-provision · session 순서 · RLS bypass · cookie · CSRF · audit)
  - Next.js App Router 패턴 위반 (RSC vs client · cookies() · Server Action · bound action · revalidatePath)
  - TypeScript 타입 안전성 (branded types · narrow · exhaustive)
  - 운영 시나리오 미커버 (concurrency · race · failure mode)

## 비평 산출물 형식

### A. Finding 리스트

```
- id: ADMIN-UI-WEB-NN
  severity: major | minor | nit
  location: "<file>:L<line>" 또는 "<file> § <section>"
  issue: "<무엇이 문제인가 — 1~3문장>"
  rationale: "<왜 문제인가 — SoT 또는 코드 직접 인용>"
  suggestion: "<close 권고 · defer 권고 · 추가 검토 권고>"
  closeableAfterPatch: true | false
```

severity 기준:
- **major**: Plan v1.0 불일치 · API 시그니처 호출 오류 · 보안 결함 · RLS bypass · runtime crash 가능
- **minor**: 일관성 부족 · 타입 narrow 부족 · code smell · 운영 미커버
- **nit**: 문구 · 표현 · import 정리 · 주석

## 중점 검증 항목 (체크리스트)

1. **Plan v1.0 ↔ 코드 정합**
   - § 3.2 인증 흐름 5 step 모두 코드 구현 (1: 발급 + allowlist, 2: consume + lookup + membership 검증 + session, 3: page resolve, 4: saveClinicProfile, 5: sign-out)
   - § 5.2 slugResolver `(sqlBase, slug, actorUserId)` 시그니처
   - § 5.3 withSkeletonTx 2단계 패턴 (resolve + withTenantTransaction)
   - § 5.4 deny-reason-map 17 AuthDenyReason exhaustive (assertNever)
   - § 5.5 audit event matrix 모든 event 구현 + audit_event 사용 (audit_log 미사용 in skeleton)
   - § 6.1 입력 필드 + zod 검증 표
   - § 6.2 Server Action — bound action · ctx.instanceId 강제 · assertActionEligibility · audit best-effort
   - § 7 환경 변수 표 (WEB_DATABASE_URL · SEED_DATABASE_URL · RESEND_MODE 허용값 등)
   - § 7.1 seed CTE upsert (instance_membership partial unique predicate + deactivated_* NULL 복귀)
   - § 9 게이트 #10 항목 모두 실현 가능

2. **packages 실 export 시그니처와 호출 정합**
   - `consumeMagicLink(sql, identifier, tokenPlain) → identifier (string)` — userId 반환 아님
   - `createSession(sql, cfg, userId) → { signedToken, row }`
   - `getActiveSession(sql, cfg, signedToken) → SessionRow` (userId: string · branded 아님)
   - `resolveTenantContext(sql, cfg, signedToken, instanceId) → TenantContext` (instanceId: string)
   - `withTenantTransaction(sql, { instanceId: InstanceId }, fn)` — branded
   - `emitAuditEvent(sql, input)` — input.eventType · actorUserId · targetUserId · payload · reason 필드명 (camelCase)
   - `assertActionEligibility(ctx, action)` — 14 ActionType
   - `getMockMailbox() → ReadonlyArray<{ to, tokenPlain, at }>` — Map 아닌 Array

3. **DB schema 정합**
   - `clinic_profile` 컬럼명 (snake_case in raw SQL · camelCase in Drizzle)
   - `admin_user.displayName` quoted camelCase (Auth.js compatible · ADMIN-UI-64·82)
   - `"session"` · `"verificationToken"` quoted camelCase
   - `instance_membership_active_unique (user_id, instance_id) WHERE active=true` partial unique
   - `instance_membership_deactivated_consistency` CHECK
   - `audit_event` columns (`occurred_at` · `actor_user_id` · `target_user_id` · payload · reason)
   - `audit_log.instance_id NOT NULL` (web seed 가 audit_event 사용해야 하는 이유)

4. **보안 결함**
   - allowlist 체크 시점 (magic-link 발급 전 · consume 전)
   - session 발급 순서 (검증 모두 통과 후만 cookie set)
   - ctx.instanceId 강제 (FormData 변조 무시)
   - assertActionEligibility 호출 위치 (tx 진입 직후)
   - cookie tampering audit 흐름
   - mock mailbox UI 노출 가드 (server-side 3중)
   - enumeration 방지 (allowlist 미존재 시 generic 응답)
   - audit_event INSERT 가 tx 안 vs 밖 (app_tenant_user GRANT 없음)

5. **Next.js App Router 패턴**
   - Server Component 안 `cookies().set` 금지 (Route Handler / Server Action 에서만)
   - bound action 패턴 (page 에서 instanceSlug bind)
   - useFormState + useFormStatus (client component)
   - `redirect()` vs `notFound()` (next/navigation)
   - revalidatePath · revalidateTag 사용
   - middleware 미사용 결정 (Plan W-03)
   - transpilePackages 또는 monorepo workspace import
   - serverActions.bodySizeLimit (Plan ADMIN-UI-39)

6. **TypeScript 타입 안전성**
   - branded types 변환 (`asUuidV4(...) as InstanceId`)
   - exhaustive switch + assertNever (deny-reason-map)
   - Drizzle `eq()` vs raw SQL tagged template 일관성
   - zod transform + nullable 정합
   - import path (`@/lib/...` alias) 정합

7. **운영 시나리오**
   - concurrent two operator save race (last-writer-wins audit payload)
   - session race during tx (request-시작 snapshot)
   - oversized body limit
   - mock mailbox replay (consumedAt NOT NULL · CAS)
   - HMAC tampering → cookie clear → audit reason
   - membership 없음 → session 미발급 (ADMIN-UI-76)

8. **seed script**
   - SEED_DATABASE_URL precondition
   - SYSTEM_ACTOR_ID 고정 UUID + display_name='System'
   - instance_membership reactivate CTE (deactivated_* NULL 복귀)
   - audit_event INSERT (audit_log instance_id NOT NULL 회피)
   - idempotency (재실행 시 동일 결과)

9. **config 파일**
   - apps/web/package.json dependency 정합 (workspace:*)
   - next.config.mjs transpilePackages
   - tsconfig path alias `@/*`
   - tailwind.config.ts content paths
   - .env.example 모든 필수 env

10. **운영 / 운영자 메시지**
    - 한국어 메시지 일관성 (Plan SoT 정합 — 사용자 본 모노레포는 한국어 메시지 기준)
    - 에러 메시지 enumeration leak 없음
